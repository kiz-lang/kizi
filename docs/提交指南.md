## 提交Pull-Request(PR)
**重要**
PR类型
- Bug修复: 添加bug的简要说明(如果有issue则进行关联)
- Feature: 提交的特性必须是kiz标准文档确定的特性, **否则不合并**
- 库: 添加库所有要注册到`kiz std modules`的函数/对象是的简易说明
- 性能相关改动请附基准数据: `python3 scripts/run_benchmarks.py --save` 保存基线, 改动后 `--compare` 对比

## 提交Issue
格式
```markdown
# 标题
===
- 简要说明
```

## 提交Bug报告
格式
```markdown
# 标题
===
- 简要说明
- bug复现
```

示例
```markdown
# Decimal除法在遇到负数时无法工作
===
- Decimal除法在遇到负数时无法工作, 直接段错误
- bug复现:
`\`\`kiz repl
>>> 0.1 / - 0.0.1
0.1
`\`\`
```

```markdown
===
```

```markdown
- 所请求的相关语法:
`\`\`kiz
expression |> func_name1 |> func_name2
`\`\`
```

## 版本号管理（维护者）

版本号的**唯一事实源**是仓库根目录的 `VERSION` 文件。发布新版本只需一条命令：

```bash
python3 scripts/bump_version.py 0.10.0     # 指定完整版本号
python3 scripts/bump_version.py --minor    # 或按语义递增：--major / --minor / --patch
```

脚本会自动更新 `VERSION` 文件与 `README.md` 的版本标题，并扫描仓库中残留的硬编码旧版本号作出提醒。三个构建系统（Make / CMake / xmake）在构建时都从 `VERSION` 读取版本号生成 `version.hpp`：

| 构建系统 | bump 后获取新版本号 |
|---|---|
| make | 直接 `make`（自动生效） |
| CMake | 重新配置：`cmake -B build && cmake --build build` |
| xmake | 重新配置：`xmake f -c && xmake`（configvar 在配置期快照） |

**不要**手动编辑 `Makefile` / `CMakeLists.txt` / `xmake.lua` 里的版本引用——它们已经没有硬编码版本号了；也不要手动改 `README.md` 的版本标题，交给脚本统一处理。
