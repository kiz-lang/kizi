## 为什么要投喂

大模型没见过 kiz 的语料，会本能地把它当成 Python/Ruby 的变体来写，然后掉进差异坑里（`elif`、`continue`、字典 `=`、引用语义……）。解决办法很简单：**每次对话开头把语法手册、内置库手册和示例喂给它**，并明确列出与 Python 的差异点。

## 给 AI 的差异提示清单

即使喂了文档，AI 仍会犯以下错误。把这份清单直接贴在提示词里：

```
写 kiz 代码时严格遵守：
1. 块用 end 结尾（if/while/for/fn/object/try 都要），没有缩进语块，行尾没有冒号
2. 没有 elif，写 else if；没有 continue，写 next
3. 字典字面量用冒号：{"a": 1}，不是 {"a" = 1}
4. 幂运算符是 ^，不是 **；没有 // 整除，整数结果用 Int(a / b)
5. 除法 / 的结果可能是 Decimal（1/3 是 0.3333333333）
6. 空值是 Nil 不是 None；print(Nil) 输出 "Nil"
7. 方法定义第一个参数是 self（惯用名 this）：fn method(this, x) ... end
8. 对象系统是原型链：object Name: Parent ... end 声明，create(Name) 实例化
9. 错误处理：try ... catch e (ErrorName) ... end；throw Error("名字", "消息")
10. 赋值是值语义：b = a 深拷贝列表/字典；共享状态用 Object 包裹并用方法修改
11. f-string：f"{表达式}"；字符串转义支持 \n \t \uXXXX
12. 下标不支持负数；len(x) 对 List/Str/Dict 通用；注释用 #
13. 闭包内修改外层变量必须写 nonlocal n = ...，直接赋值会创建局部变量
14. 不要用 ensure/finally、match、链式比较、多变量交换、类型标注
```

## 验证闭环

AI 写的 kiz 代码**必须**实际运行验证：

```bash
kiz run task.kiz          # 运行整个文件
kiz repl                  # 交互验证小片段
```

把报错信息（kiz 的 traceback 自带源码行号与箭头定位）原样贴回给 AI 让它修，通常一两轮就能收敛。kiz 的错误信息格式：

```
File "task.kiz"
3 |     print(x
              ^
SyntaxError : Unclosed argument list
```

## 常见失败模式

- **AI 坚持写 Python**：说明投喂材料没生效，重开对话，把差异清单放到最前面。
- **AI 发明不存在的内置函数**（如 `split`、`lower`）：让它只使用《内置对象&库速览》中列出的函数；kiz 字符串方法是小写驼峰式（`tolower` 不是 `lower`）。
- **AI 忘写方法第一个 self 参数**：kiz 方法第一个参数接收调用者对象，这是硬性约定。
- **AI 依赖引用语义**：提醒它 `b = a` 是拷贝，需要共享时用 `create()` 包一层并用方法修改。
- **复杂单行表达式**：kiz 的多行结构（fn/object）比单行 lambda 更稳，让 AI 优先用多行形式。
